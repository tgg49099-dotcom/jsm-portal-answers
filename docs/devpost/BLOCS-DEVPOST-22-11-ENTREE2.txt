=== DEBUT TITRE ===
JSM Portal Answers - read-only MCP answers for JSM portals
=== FIN TITRE ===

=== DEBUT DESCRIPTION ===
JSM Portal Answers answers a customer's question about a Jira Service Management customer portal, with two read-only tools exposed through the official Atlassian rovo:mcp module. An agent can ask what a customer can request on a portal, and what the create form of a request type asks for, and get the answer from the portal itself instead of guessing. The tools read with the caller's own Jira permissions: they write nothing, store nothing, and call no external service.
=== FIN DESCRIPTION ===

=== DEBUT DESCRIPTION_ETENDUE ===
list_portal_request_types answers "what can I ask for here?". It lists the request types a customer can raise on a portal: their description, their category, whether the caller may raise them, and the portal rules.

describe_request_type_form answers "what do I have to fill in?". It describes the create form of one request type: every field, with its label, whether it is required, its type, its help text and its possible values.

Read live from a Jira Service Management portal on 18 November 2026: the first tool answered that the portal SUP has 9 request types and 5 categories; the second answered, for the request type "Get IT help", that the form has three fields (Summary, required; Description; Attachment), that a request can be raised on behalf of another person, and that participants can be added.

What the app does not do: it never writes (every call is a GET), never stores anything, never calls an external service, and never uses the app's own identity (every read goes through asUser()). It never claims what the API does not say: the SLA targets of a portal are not exposed by the public JSM REST API, and the tools say so instead of inventing one.
=== FIN DESCRIPTION_ETENDUE ===

=== DEBUT BONUS ===
Submitted for the bonus "Best app with Atlassian MCP": a Forge app that exposes tools via the Atlassian MCP server using the rovo:mcp module.

The other submission of this project, "Portal Accessibility Checker for JSM", is substantially different:

- Purpose: the other app audits a portal for WCAG 2.2 AA issues and returns findings to verify; this app reads the metadata of the portal and answers a customer's question.
- Audience: the other app answers to Jira administrators and checks the administer permission; this app declares no administrator permission. Its audience is whoever answers a customer: an agent, or an MCP client acting for them.
- Data: the other app reads the content customers fill in and the issues of the site; this app reads request type metadata, categories and form fields, nothing else.
- Code: two different code bases (this repository: tgg49099-dotcom/jsm-portal-answers), two different sets of handlers, no shared engine.
- Outcome: a list of findings to review, against an answer an agent can relay to a customer.

This app declares one rovo:mcp module, two read-only tools (actionVerb: GET), and one scope, read:servicedesk-request.

=== DEBUT INSTALLATION ===
1. Open the installation link of this app (the block below), choose the Jira Service Management site to install it on, and accept the read scope read:servicedesk-request.
2. Open the app once in Jira. The site records your consent for Jira Service Management that way, and the tools read with your own permissions, so nothing else is needed.
3. A site administrator must enable the app in the Atlassian MCP server administration of the site: external MCP exposure is off by default on a site. After that step, any MCP client can call the two tools.
4. Ask the MCP client for list_portal_request_types and describe_request_type_form. The first takes an optional portal (a service desk id or a project key such as SUP) and optional question words, which are passed to the server-side search filter of the JSM API. The second takes the request type, by id (1) or by exact name ("Get IT help"), and an optional portal.
5. The answer arrives as text. Nothing is written and nothing is stored.
6. The same two answers are in the browser: in Jira, open the Apps menu and choose "JSM Portal Answers". The page calls the very same tools, so it cannot disagree with them.

For developers: npm install, then npm test (the offline harness, its counter-proof and the static rules), then forge deploy to your own site. The two tools are src/mcp.js; the only file that talks to the Atlassian API is src/jsm.js, and every one of its calls is a GET.

=== DEBUT TECH ===
Stack: Atlassian Forge, one rovo:mcp module, two read-only actions (actionVerb: GET), one jira:globalPage rendered with UI Kit 2 and React 18, three Node.js functions on the nodejs24.x runtime (256 MB, arm64), @forge/api 8.5.0, plain JavaScript with no other runtime dependency. The app reads the JSM Cloud REST API v3 (read:servicedesk-request) and is exposed to agents through the Atlassian MCP server.

Main technology requirement: it is a Forge app that integrates with two Atlassian capabilities: Jira Service Management, whose customer portal it reads, and Rovo, whose MCP server carries its two tools through the official rovo:mcp module.

Application id: ari:cloud:ecosystem::app/c88fa86b-4c89-4634-9d08-53f3cdfab803. The version in production is 2.0.0, deployed on 18 November 2026 and installed on the test site. The app was registered for this contest and has never been published to the Marketplace.
=== FIN TECH ===
